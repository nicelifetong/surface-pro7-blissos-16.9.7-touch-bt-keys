# 06 存储显示 2T、已用 95%

## 现象

128G 的盘，设置 → 存储里显示总量 **2 TB**、已用 95%，看着很难受。

## 根因

KernelSU 的模块镜像 `/data/adb/ksu/modules.img` 默认是 **1 TiB 稀疏文件**
（`ls -l` 显示 1099511627776 字节，实际只占几 MB），它被挂载到
`/system` 和 `/data/adb/modules` 两处：

```
/dev/block/loop7   0.9T  92K  0.9T   1% /data/adb/modules
KSU                0.9T  92K  0.9T   1% /system
```

Android 的存储统计按**表观大小**累加，两个挂载点加起来 ≈ 2 TB。

真实可用空间没变（`df -h /data` 仍是 109G/100G）。

## 修复

把模块镜像缩到 4 GiB（实测模块不受影响）：

```sh
su -c 'sh /data/local/tmp/shrink-module-image.sh'
```

脚本做的事：

1. 备份 `/data/adb/modules` 到 `/data/local/tmp/ksu_backup`
2. 新建 4 GiB 镜像并 `mke2fs`
3. 挂载新镜像、把模块文件原样拷进去
4. 改名替换（旧文件保留为 `modules.img.old`）

**重启**后生效，然后删掉旧镜像：

```sh
su -c 'rm -f /data/adb/ksu/modules.img.old; df -h /system'
```

`/system` 会从 `0.9T` 变成 `3.8G`。

## 为什么不直接 `ksud module shrink`

该命令会先跑 `e2fsck -f`，而镜像正被挂载使用，会失败：

```
Please run 'e2fsck -f /data/adb/ksu/modules.img' first.
```

所以要「新建镜像 + 拷贝 + 替换 + 重启」。

## 注意

换盘重装后 KernelSU 会重新生成 1 TiB 镜像，需要再跑一次。
