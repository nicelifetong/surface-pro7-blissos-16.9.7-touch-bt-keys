# 附加 01 时间快 8 小时

## 现象

双系统（Windows + BlissOS）来回切换后，Android 时间比实际**快 8 小时**。

## 根因

RTC 里存的是 Windows 写入的**本地时间**（CST），而 Android/Linux 默认把 RTC 当 UTC 读，
于是 +8 小时。

彻底修法是让 Windows 把 RTC 当 UTC 写（注册表 `RealTimeIsUniversal=1`），
但在本机这个 Bliss 构建上改完系统时间会被 RTC 又覆盖，所以用「开机强制 NTP 对时」更稳。

## 修复

```sh
su
settings put global ntp_server ntp.aliyun.com
# 触发 NetworkTimeUpdateService 重新同步
settings put global auto_time 0; sleep 1; settings put global auto_time 1
```

做成开机自动（`scripts/service.sh` 里已有这段），重复 3 次提高成功率。

## 验证

```sh
date; settings get global auto_time   # 1
dumpsys time_detector | head -20      # 看 NTP 是否 confirmed
```

## 备注

- 国内用 `ntp.aliyun.com`；其它地区换 `time.google.com` / `pool.ntp.org`。
- 若 RTC 本身偏差很大（不是整 8 小时），先换主板电池或检查 Windows 的时区设置。
