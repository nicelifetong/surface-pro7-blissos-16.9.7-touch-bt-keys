# 05 摸着摸着突然息屏

## 现象

正常滑动/点按时，屏幕毫无预兆地息屏；不是超时（超时被设成了 166 小时）。

## 诊断

`logcat` 里能看到明确的调用者：

```
PowerManagerService: Going to sleep due to application
  (uid 10256, millisSinceLastUserActivity=-220, lastUserActivityEvent=touch)

PowerGroup: Powering off display group due to application (uid=10256, ...)
```

`uid 10256` = `com.android.launcher3`，且紧跟在一次 `touch` 之后。

## 根因

Launcher3 的 **sleep gesture（双击桌面空白处休眠）** 默认开启，
连续点击时被误判成双击，于是主动息屏。

对应的偏好键：`pref_sleep_gesture`。

## 修复

写入 Launcher3 的偏好文件（需在桌面未运行时改，或改完强制重启桌面）：

```sh
su
LP=/data/data/com.android.launcher3/shared_prefs/com.android.launcher3.prefs.xml
cp "$LP" "$LP.bak"
grep -q pref_sleep_gesture "$LP" \
  && sed -i 's/name="pref_sleep_gesture" value="true"/name="pref_sleep_gesture" value="false"/' "$LP" \
  || sed -i 's#</map>#    <boolean name="pref_sleep_gesture" value="false" />\n</map>#' "$LP"
chown $(stat -c %u /data/data/com.android.launcher3):$(stat -c %g /data/data/com.android.launcher3) "$LP"
chmod 660 "$LP"
am force-stop com.android.launcher3
```

更稳的做法是在 **post-fs-data** 阶段改（桌面还没起来，不会打架），
参考 `scripts/post-fs-data.sh`。

## 验证

在桌面空白处故意双击：不再息屏。日志里不再出现
`Going to sleep due to application (uid 10256)`。

## 顺带说明

息屏会真正挂起设备，`iptsd` 的 hidraw 读取会报
`Reading from file failed: I/O error` 并退出，唤醒后需要重新拉起——
所以「唤醒后头一两秒没触控」是正常的，不是参数问题。
