# 01 触屏被识别成「触控板」

## 现象

安装好 BlissOS Surface 版后，手指划屏幕只会移动一个鼠标光标（像笔记本触控板），
不能点按、没有多点，笔却可以正常用。

## 根因

Surface Pro 7+ 的触屏走 **Intel THC**（`045E:0C1A`），Android 侧需要 `iptsd`
（linux-surface 的用户态守护进程）把原始数据转成 input 事件。

而这批构建里：

- `/system/vendor/bin/iptsd-find-hidraw` 是 **bash 脚本**（依赖 `BASH_SOURCE`、
  `source`、数组等），Android 的 `sh`(mksh) 跑不了；
- 开机时 `init.sh` 执行 `start iptsd_runner`，runner 内容是
  `iptsd $(iptsd-find-hidraw)`，脚本一失败，iptsd 带空参数退出；
- 内核日志里能看到它每 5 秒重启一次：

```
init: starting service 'iptsd_runner'...
init: Service 'iptsd_runner' (pid 1449) exited with status 106
```

- 剩下能用的只有内核 HID 的**单点回退设备**，Android 把它归类成 touchpad。

## 修复

手动（或开机脚本）用正确路径启动 iptsd：

```sh
# 确认二进制位置（注意是 /system/vendor/bin）
ls /system/vendor/bin/iptsd*

# 找 IPTS 设备并启动
for h in /dev/hidraw*; do
  /system/vendor/bin/iptsd-check-device --quiet --type=any "$h" && \
    /system/vendor/bin/iptsd "$h" &
done
```

`scripts/start-iptsd.sh` 做了完整处理：路径探测、已有进程检查、逐个 hidraw 试探、
日志写入 `/data/local/tmp/iptsd-fix.log`。

## 验证

```sh
getevent -pl | grep -A3 IPTSD
```

应出现两个设备：

```
"IPTSD Virtual Touchscreen 045E:0C1A"   ← 多点触控
"IPTSD Virtual Stylus 045E:0C1A"        ← 笔（压感/倾斜）
```

`dumpsys input` 里该设备应为 `Classes: TOUCH | TOUCH_MT`。

## 备注

官方已在 2025-04 重写了这套启动逻辑（新增 `iptsd` service、`vendor.iptsd.device`
属性、`set_iptsd_device` 脚本、唤醒后重启），2025-05 之后的构建不再需要这个补丁。
见 [BlissOS/device_generic_common@85533bc](https://github.com/BlissOS/device_generic_common/commit/85533bce0369a48c57045a46f61ba51cb91559d5)。
