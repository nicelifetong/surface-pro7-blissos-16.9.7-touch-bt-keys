# 07 音量键失灵（按键驱动加载顺序）

## 现象

Surface Pro 7+ 上 BlissOS 16.9.7（内核 6.1.112-gloria-surface-xanmod1）：
**音量加减键完全没反应**，电源键正常。

## 诊断

```sh
getevent -pl | grep -i -e gpio -e power
```

只有：

```
name: "Android Power Button"
  KEY (0001): KEY_POWER  KEY_WAKEUP
```

没有 `gpio-keys` 设备。

再看设备绑定：

```sh
su -c 'ls -l /sys/bus/platform/devices/MSHW0040:00/driver'
# ls: ... No such file or directory     ← 按键的 ACPI 设备没有绑定任何驱动
```

`MSHW0040` 是 Surface 的按键 ACPI 设备，正常应该由 `gpio-keys` 接管并导出
`KEY_POWER` + `KEY_VOLUMEUP/KEY_VOLUMEDOWN`。

## 根因

**驱动加载顺序竞争**：`soc_button_array`（Intel SoC 按键阵列驱动，本机根本没有
`PNP0C40` 设备可用）先加载时占住了 GPIO 资源，等 `gpio_keys` 去 probe `MSHW0040`
时资源不可用，绑定失败，于是音量键没有任何 input 设备。

这也解释了为什么「有的机器刷完第一次能用、重启后失效」——谁先谁后是竞态。

## 修复

让系统**延后加载** `soc_button_array`：

```sh
su -c 'printf "deferred soc_button_array\n" > /data/vendor/modules.blocklist'
reboot
```

重启后：

```sh
su -c 'dmesg | grep -i gpio-keys'
```

出现两条：

```
input: gpio-keys as /devices/platform/MSHW0040:00/gpio-keys.1.auto/input/input45
input: gpio-keys as /devices/platform/MSHW0040:00/gpio-keys.2.auto/input/input46
```

```sh
getevent -pl | grep -A1 gpio-keys
# name: "gpio-keys"   KEY (0001): KEY_POWER
# name: "gpio-keys"   KEY (0001): KEY_VOLUMEDOWN  KEY_VOLUMEUP
```

音量键、电源键都回来了。

## 注意

- 该文件由 init 在**很早**的阶段读取，所以改完必须**重启**，不能只重启 zygote。
- 文件不存在时系统行为不变；删掉它就回到「按键失灵」的默认状态。
- 如果重启后仍然只有 `Android Power Button`，说明该内核版本把按键逻辑挪到了别处
  （或 `soc_button_array` 被编译成内建而非模块），`deferred` 就不起作用了，
  需要内核侧补丁或者换构建。
